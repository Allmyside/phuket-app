# Курсы: расчёт и проверка (v10, 15.11.2026)

## Расчёт

Режим USD 2009+ включён по умолчанию. Для каждого банка редактируются фиксированный сбор, наценка в ₽/$ и её минимум в ₽.

Для N > 0 полная стоимость:

`RUB = N × sell + max(minimum, N × premium) + fee`.

Обратный расчёт для рублёвого бюджета B:

`N = max(0, min((B − fee − minimum) / sell, (B − fee) / (sell + premium)))`.

При выключенном режиме и для EUR/CNY premium и minimum равны нулю. За нулевую покупку сбор не начисляется. До выбора оптового курса проверяется возможность оплатить пороговую сумму вместе со всеми сборами. Для Лиговки пороги USD/EUR — 1000 и 10000, CNY — 10000 единиц. При текущих курсах нижние рублёвые пороги — 85 320 / 94 820 / 128 420 ₽.

Для ввода иностранной валюты сначала определяется минимальная полная стоимость покупки целевого количества. Все 14 маршрутов затем сравниваются на этот единый бюджет. В строке целевой валюты дополнительно указывается стоимость исходного количества в конкретном банке. Количество валюты не округляется до банкнот; это прямо указано в интерфейсе.

В каждой строке: расходы в RUB, получение THB, эффективный курс, разница с лидером группы в THB и её справочный эквивалент в RUB. Рублёвый эквивалент потери — разница THB × официальный RUB/THB, а не дополнительный счёт банка. Карточки групп также сравниваются между собой. Карточка уже имеющихся наличных сравнивает только обменники Пхукета; новых расходов RUB там нет. Для EUR/CNY нет биржевого кросс-курса, поэтому биржевая комиссия не выдумывается.

## Парсеры и хранение

Общая проверка validRateValue применяется к строгим и резервным парсерам, кэшу, ручному вводу и расчёту. Диапазоны включительны: USD/RUB 65–130, EUR/RUB 75–150, CNY/RUB 9–20. Проверяются также оптовые ставки, направление buy/sell, город и заголовок валюты для резервных страниц. Неверная котировка не заменяет сохранённую.

Ключи: `confirmed-live-rates-v10`, `rate-manual-overrides-v10`. Старые версии не читаются; ручные значения v10 тоже проходят проверку при восстановлении. Тарифные поля хранятся отдельно от курсов, поэтому ответ страницы с USD/EUR/CNY не удаляет наценку. Кэш Service Worker обновлён до v16. Пользовательские профили не восстанавливают поля котировок.

Кнопка обновления опрашивает восемь групп источников, использует таймауты и сохраняет корректные частичные ответы. При отказе сети цены и тарифы сохраняются; статус показывает фактический результат. Сборщик scripts/update-rates.mjs использует те же парсеры, проверяет старый снимок и сохраняет JSON/seed через временные файлы.
